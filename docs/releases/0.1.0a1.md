## Repository gate

The exact candidate passed the active-source repository gate in the `mantra`
Conda environment with Python 3.14.6:

```bash
ruff check viper tests examples/project/src tools
ruff format --check viper tests examples/project/src tools
pyright --pythonpath "$(command -v python)"
python tools/audit_contracts.py
python -m pytest tests -q
```

Ruff and Pyright reported zero errors. The contract audit passed with 10
contracts, 73 parsed Python blocks, 51 repeated classes, 8 repeated aliases,
136 generated Pydantic schemas, and 63 traced verifier rules. Pytest reported
218 passed tests, 6 hardware-gated skips, and 33 passed subtests in 368.97
seconds.

GitHub Actions run
[`32723982759`](https://github.com/pvd232/BioStats/actions/runs/32723982759)
passed for the exact candidate commit under Python 3.11, 3.12, 3.13, and 3.14.

## Observed warnings

Two resume tests report TorchData's upstream `set_vital` deprecation warning.
The copied live-CUDA test package reports an unknown-marker warning because the
external test directory omits the repository's pytest configuration. Both test
groups pass.

One initial macOS Python 3.14 clean-checkout run encountered a process-launch
segmentation fault while a test HTTP server thread was active. The isolated
tests passed immediately afterward, and the complete clean-checkout rerun
passed. The exact candidate also passed the complete local suite and the Linux
CI matrix.

## Publication blockers

Publication requires four owner actions:

1. Select the package license and author metadata.
2. Provide TestPyPI credentials through the configured credential provider.
3. Authorize publication of the validated files to PyPI.
4. Provide the release-tag signing identity and configuration.

The files listed above remain the release candidate. Any source or metadata
change requires a rebuild and repetition of the distribution, installed-wheel,
CI, and GCE gates.
